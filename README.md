# workbuddy-seq-runner：凌晨按号顺序跑任务 + 按号账本

状态：**只写代码、不安装**。本仓库不碰路由器，不含任何账号
凭证，不含任何真实 WorkBuddy token。将来是否安装、装在哪、
怎么与 hub 并存，都要用户另行点头。

## 这个项目到底改了什么

借鉴 workbuddy2api-hub，但调度策略不同。hub 的做法是：

- 签到 09:00/21:00、旅行 09:00/21:00、夜猫 01:00、国际活跃
  随机时段，任务拆在多个整点；
- 签到/旅行那一轮是按号顺序跑，号间只隔 2-5 秒；
- 国际活跃那一批可以并行跑，还有批次截止时间，到点就丢
  下剩余账号。

本项目的做法是（用户已拍板）：

1. **凌晨一趟，按号顺序跑完。** 一个号的全部任务（国内：
   签到、活跃上报、成长任务、猫猫旅行、连登、夜猫；国际：
   每日活跃）在同一趟里跑完，跑完一个号再跑下一个。
2. **号间隔是分钟级、随机的**（默认 15-40 分钟，见
   `config.example.json`），不是 2-5 秒。
3. **主队列没有截止时间。** 跑得再长，剩下的号也接着跑完，
   不像 hub 的活跃批次那样到点丢号。
4. **失败的号不挡队、不立即重试。** 主队列跑完、隔一段时间
   （默认 1-1.5 小时）后，同一天清晨开一个补跑队列；每个号
   每天最多补跑 1 次；只补 transient 失败（超时、网络、
   11128），11140、token 过期、已领取不补跑，直接进冷藏/
   待手动处理。
5. **跑任务与消费积分是两条线，互不干扰。** 调度器不查
   代理取号状态、不等账号空闲；消费侧（dsh、小龙虾走 hub
   的 OpenAI 接口）也不被调度器暂停。唯一的硬跳过是上游
   风控限制（restricted / 11140），那是防连坐，不是消费锁。
6. **每个号有账本，账本接进 hub 现有看板。** 不是另起一个
   看板：见 `dashboard_fragment.html` + `panel_patch.md`，
   账本出现在 hub 看板任务页里。

## 文件

- `seq_runner.py`：顺序队列 + 补跑队列 + 错误分类 + 排序。
  不含任何 WorkBuddy API 调用。
- `ledger.py`：按号账本。`ledger.jsonl` 是追加流水，
  `snapshot.json` 是每号最新快照（看板读它）。
- `hub_adapter.py`：把 hub 的 `wb_tasks` / `Account` 方法
  （签到、成长任务、猫猫旅行、连登、夜猫、国际活跃）接
  到顺序队列上。只在将来与 hub 同目录部署时才可用。
- `run.py`：命令行。`--dry-run` 是唯一可以在本仓库里
  安全跑的模式；`--hub` 目前是被拒绝的桩（guarded stub），
  防止半部署。
- `config.example.json`：窗口、间隔、补跑间隔示例。
- `dashboard_fragment.html` / `panel_patch.md`：账本进
  hub 看板的方法。
- `tests/test_seq_runner.py`：标准库单测，无网络。

## 账本记什么

快照（每号一行）：区域、上次状态、上次阶段（主/补跑）、
上次余额、连续失败次数、是否待次日确认、下一步（补跑/
冷藏/待手动）。

流水（每号每天至少一条，补跑追加一条不覆盖）：开始结束
时间、跑了哪几项任务、每项结果、跑前跑后余额与差值、
错误码、待次日确认标记。

次日到账的奖励（例如国际每日活跃）跑完当时只记
“已提交”，下一次跑该号时先用任务自身状态复核（例如
`can_daily_chat` 已为假），再改成已确认/未确认。**不用
余额差值来确认次日奖励**，因为白天消费也会动同一余额。

## 先说清楚的未决项（写代码时故意没编造）

- **两边的每日重置时刻还没定。** 国内版和国际版不一定
  都是北京时间午夜重置，开始时间要定成“重置时刻 + 随机
  延迟”，而不是写死 01:00。定之前要连续看几天两边的
  任务状态时间戳。`config.example.json` 里的 01:00-02:30
  只是示例窗口。
- **与 hub 调度器并存的规则还没定。** 凌晨队列接管后，
  hub 自带重叠时段要关掉或改期（见 `panel_patch.md`），
  否则两个调度器轮流尝试同一批任务。
- **真实账号验证还没做。** 本仓库的单测和 `--dry-run`
  只验证调度与账本逻辑；真实 WorkBuddy 任务链必须在
  将来安装后、拿一个不重要的号先跑一轮、核对积分到账
  后再扩到全部号。
